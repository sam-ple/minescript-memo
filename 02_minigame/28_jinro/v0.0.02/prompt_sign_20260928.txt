# ============================================================
# 人狼RPG｜看板登録システム 開発プロンプト
# ============================================================

あなたは Minecraft Java Edition の Skript 開発者です。

現在、Paper + Skript 2.16.1 環境で「人狼RPG」を開発しています。

このプロンプトでは、人狼RPGにおける
「プレイヤーと看板を紐づける看板登録システム」
を開発・改善してください。

============================================================
【開発環境】
============================================================

Minecraft Java Edition
Paper
Skript 2.16.1

現在は Minecraft 26.2 系で開発・テストしています。

基本方針：

・まずミニテストとして単体動作を確認する
・動作確認後、占い・騎士の加護などのゲームシステムへ組み込む
・できるだけSkript標準機能を使用する
・必要な場合のみMinecraftコマンドを使用する
・既存の動作している部分を不用意に変更しない
・エラーが出た場合は、動作している部分を残して最小限修正する


============================================================
【このシステムの目的】
============================================================

人狼RPGでは、プレイヤー本人を直接クリックするのではなく、
「プレイヤーに対応した看板」をクリックして対象プレイヤーを選択する。

例えば、

看板A
 ↓
crocadooo
 ↓
役職：人狼

という関係を作る。

将来的には、この看板をクリックして、

・占い
・騎士の加護
・その他のプレイヤー選択型能力

を実行する。

そのため、

【看板 ↔ プレイヤー】

の紐づけが、このシステムの最重要機能。


============================================================
【重要な設計思想】
============================================================

PLAYER 1
PLAYER 2
PLAYER 3

などの「登録番号・スロット番号」は不要。

プレイヤー番号をゲーム上のIDとして使わない。

必要なのは、

【看板座標 → プレイヤーUUID】

および

【プレイヤーUUID → 看板座標】

の2方向の紐づけだけ。

例：

{jinro.sign.player::<看板座標>}
    ↓
プレイヤーUUID

{jinro.player.sign::<プレイヤーUUID>}
    ↓
看板座標

プレイヤー名は表示用として別途保存してよい。

{jinro.player.name::<プレイヤーUUID>}
    ↓
プレイヤー名


============================================================
【登録モード】
============================================================

看板登録は常時可能にはしない。

以下のコマンドで登録モードを切り替える。

/jinrosignsetstart

→ 看板登録モード開始


/jinrosignsetend

→ 看板登録モード終了


登録モード中だけ、
未登録の看板を右クリックすると登録できる。

登録モードOFFの場合、
未登録看板を右クリックしても登録しない。


============================================================
【看板登録】
============================================================

登録モード中に未登録の看板を右クリック。

以下を実行する。

1. クリックした看板の座標を取得

2. クリックしたプレイヤーのUUIDを取得

3. そのプレイヤーがすでに登録されているか確認

4. すでに登録されていた場合は登録しない

5. 未登録なら、

   看板座標
       ↓
   プレイヤーUUID

   プレイヤーUUID
       ↓
   看板座標

   を保存する。

6. プレイヤー名を保存する。

7. 看板にプレイヤー名を表示する。

8. 看板の1ブロック上にプレイヤーヘッドを設置する。


============================================================
【同じプレイヤーの二重登録】
============================================================

同じプレイヤーが2枚以上の看板に登録されないようにする。

例：

crocadooo
 ↓
看板A

の状態で、看板Bをクリック。

→

「あなたはすでに登録されています。」

として登録しない。


============================================================
【自分の看板を再クリックした場合】
============================================================

登録済みプレイヤー本人が、
自分に紐づいている看板を再度右クリックした場合、

【登録解除】

とする。

解除時には必ず以下をすべて実行する。

1. 看板の前面の文字を全消去

2. 看板の背面の文字を全消去

3. 看板の1ブロック上のプレイヤーヘッドを削除

4. 看板 → プレイヤーUUID の紐づけを削除

5. プレイヤーUUID → 看板 の紐づけを削除

6. 保存していたプレイヤー名を削除


解除後は完全な「空の看板」に戻す。


============================================================
【他人の登録済み看板】
============================================================

他のプレイヤーに紐づいている看板を、
別のプレイヤーが右クリックした場合。

登録解除・上書きはさせない。

例えば、

crocadooo → 看板A

の状態で、

player2 が看板Aをクリック。

→

「この看板は他のプレイヤーが登録しています。」

などのメッセージを表示する。


============================================================
【看板へのプレイヤー名表示】
============================================================

「PLAYER 1」
「PLAYER 2」

などの文字は表示しない。

プレイヤーヘッドが看板の上に存在するため、
プレイヤー名だけを表示する。

基本表示：

1行目：空白
2行目：空白
3行目：プレイヤー名
4行目：空白


例：

┌──────────┐
│          │
│          │
│ crocadooo│
│          │
└──────────┘
     👤


============================================================
【長いプレイヤー名】
============================================================

プレイヤー名が長い場合、
看板の3行目だけに無理やり詰め込まない。

表示用文字列を分割する。

通常：

3行目：プレイヤー名
4行目：空白


長い名前：

3行目：名前前半
4行目：名前後半


重要：

【保存するプレイヤー名・UUIDは分割しない】

あくまで看板表示時だけ分割する。


============================================================
【看板の前面・背面】
============================================================

看板は前面だけではなく、
背面にも同じプレイヤー名を表示する。

つまり、

FRONT

1行目：空白
2行目：空白
3行目：プレイヤー名
4行目：空白


BACK

1行目：空白
2行目：空白
3行目：プレイヤー名
4行目：空白


とする。

プレイヤーが看板のどちら側から見ても
対象プレイヤーが分かるようにする。


============================================================
【プレイヤーヘッド】
============================================================

登録時、

看板の1ブロック上に
登録したプレイヤーのスカルを設置する。

例：

看板位置
X Y Z

ヘッド位置
X Y+1 Z

プレイヤーヘッドには登録プレイヤーのスキンを使用する。


============================================================
【解除時のヘッド】
============================================================

解除時は、

看板の1ブロック上

を空気に戻す。

つまり、

プレイヤーヘッド
 ↓
air

とする。


============================================================
【RESET】
============================================================

/jinrosignreset

は、

【看板登録システム専用RESET】

とする。

人狼RPG全体のデータを削除してはいけない。

役職、
ゲーム状態、
昼夜、
アイテム、
その他の人狼RPG変数

などは削除しない。

削除対象は看板登録関連だけ。


============================================================
【RESETの処理】
============================================================

RESETでは、
現在登録されているすべての看板を対象にする。

各看板について、

1. 前面の看板文字を全消去

2. 背面の看板文字を全消去

3. 看板の1ブロック上のプレイヤーヘッドを削除

4. 看板 → UUID を削除

5. UUID → 看板 を削除

6. プレイヤー名情報を削除

最後に登録モードをOFFにする。


============================================================
【INFO】
============================================================

/jinrosigninfo

で現在の登録状況を確認できるようにする。

確認したい情報：

・登録モード ON / OFF
・現在の登録人数
・登録されているプレイヤー名
・そのプレイヤーに紐づいている看板座標

PLAYER 1
PLAYER 2

などの番号表示は不要。


例：

[JINRO SIGN INFO]

登録モード: ON
登録人数: 2

crocadooo → world:100,65,200
player2   → world:110,65,200


============================================================
【現在の基本変数】
============================================================

基本的には以下を使用する。

# 登録モード
{jinro.sign.registering}

# 看板 → UUID
{jinro.sign.player::<看板座標>}

# UUID → 看板
{jinro.player.sign::<UUID>}

# UUID → プレイヤー名
{jinro.player.name::<UUID>}


必要に応じて、

# UUID → ヘッド位置

などを追加してもよい。

ただし、不要な変数を増やしすぎない。


============================================================
【重要：UUIDを基準にする】
============================================================

プレイヤー名を内部管理のキーとして使用しない。

理由：

・名前は表示用
・将来的な名前変更への対応
・同じ名前問題を避ける
・看板とプレイヤーを確実に紐づける

内部的なプレイヤー識別はUUIDを基本とする。


============================================================
【将来の人狼RPGとの連携】
============================================================

この看板登録システムは、
後から別のSkriptファイルから利用する。

例えば、

jinro_sign.sk
    ↓
看板とプレイヤーの紐づけ


jinro_role.sk
    ↓
UUIDと役職の紐づけ


jinro_divination.sk
    ↓
海洋の心による占い


jinro_guard.sk
    ↓
騎士の加護


という構成を想定する。


============================================================
【占いとの連携予定】
============================================================

海洋の心を取得すると、
占い可能回数が増える。

占い回数を持っているプレイヤーが
対象プレイヤーの看板をクリックすると、

1. クリックされた看板を取得

2. 看板に紐づいているUUIDを取得

3. そのUUIDの役職を取得

4. 対象プレイヤーの役職を判定

5. 村人 / 人狼 / 吸血鬼
   などの結果を表示

6. 占い回数を1消費

という処理を行う。

したがって、
看板とプレイヤーの紐づけは
占いシステムの基盤になる。


============================================================
【騎士の加護との連携予定】
============================================================

騎士の加護など、
「対象プレイヤーを看板から選択する能力」
でも同じ仕組みを利用する。

例えば、

看板
 ↓
UUID
 ↓
対象プレイヤー

として対象を取得する。


============================================================
【ファイル構成】
============================================================

看板登録は独立したファイルにする。

例：

jinro_sign.sk

将来的に、

jinro_role.sk
jinro_divination.sk
jinro_guard.sk
jinro_daynight.sk

などと分離する。

看板登録システムの中に
占いや騎士の加護そのものを実装しない。

============================================================
【コード作成時の重要ルール】
============================================================

・既に動作確認済みのSkript構文を優先する
・Skript 2.16.1で使用できる構文を前提にする
・一度に複雑な機能を大量追加しない
・ミニテストとして独立して動くコードを作る
・変数構造を明確にする
・UUIDを内部識別子として使用する
・看板座標を看板識別子として使用する
・プレイヤー名は表示用として扱う
・PLAYER番号を導入しない
・解除時には看板とヘッドを必ず消去する
・RESET時にも看板とヘッドを必ず消去する
・前面だけでなく背面も処理する
・看板登録と役職判定を分離する


============================================================
【最終目標】
============================================================

人狼RPGのゲーム中に、

        プレイヤー
           ↓
      自分の看板
           ↓
       プレイヤー名
           ↓
      プレイヤーヘッド


という分かりやすい表示を作り、

その看板を他のプレイヤーがクリックすることで、

        看板
         ↓
    プレイヤーUUID
         ↓
      対象プレイヤー
         ↓
       その役職
         ↓
   占い・騎士の加護など

へつなげられる、
「プレイヤー選択の共通基盤」
として完成させる。
