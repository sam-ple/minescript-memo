# ============================================================
# 人狼RPG｜役職設定・抽選システム仕様プロンプト
# ============================================================

人狼RPGの役職設定システムをSkriptで設計する。

## 基本方針

参加者は事前に登録されているものとする。

例：

{jinro.players::1}
{jinro.players::2}
{jinro.players::3}
...

登録された人数を「参加人数」とする。

役職ごとの「最大人数」は設定しない。

参加人数を基準として、設定された役職を抽選・配置し、
最後に残った人数を村人とする。


# ============================================================
# 役職データ
# ============================================================

各役職について、最低限以下の情報を持つ。

- role
- chance
- count
- team

role
    → 役職ID

chance
    → その役職をゲームに採用する確率（0～100%）

count
    → その役職が採用された場合に配置する人数

team
    → 所属陣営


# ============================================================
# 抽選ルール
# ============================================================

「chance」と「count」は別の概念として扱う。

chance
    → その役職が存在するかどうかの確率

count
    → 存在する場合に何人配置するか


例：

vampire
    chance = 50
    count = 1

↓

50%の確率で吸血鬼が1人入る。
50%の確率で吸血鬼は0人。


例：

vampire
    chance = 50
    count = 2

↓

50%の確率で吸血鬼が2人入る。
50%の確率で吸血鬼は0人。


例：

vampire
    chance = 100
    count = 1

↓

必ず吸血鬼が1人入る。


例：

vampire
    chance = 0
    count = 1

↓

吸血鬼は絶対に入らない。


# ============================================================
# 人狼
# ============================================================

人狼は必須役職とする。

例：

wolf
    chance = 100
    count = 3
    team = wolf

↓

必ず人狼3人。


「人狼は必ず存在する」という前提で設計する。


# ============================================================
# 村人
# ============================================================

村人の人数は直接設定しない。

他の役職を確定した後、

    村人人数
    =
    登録参加人数
    -
    特殊役職の合計人数

とする。

例：

参加人数 = 10人

人狼 = 3人
吸血鬼 = 1人
狂人 = 2人
パン屋 = 1人

合計 = 7人

↓

村人 = 10 - 7

↓

村人3人


# ============================================================
# 役職設定例
# ============================================================

wolf:
    chance = 100
    count = 3
    team = wolf

vampire:
    chance = 50
    count = 1
    team = vampire

madman:
    chance = 50
    count = 1
    team = wolf

baker:
    chance = 100
    count = 1
    team = villager


# ============================================================
# 陣営
# ============================================================

roleとteamは別々に管理する。

例：

wolf
    role = wolf
    team = wolf

madman
    role = madman
    team = wolf

vampire
    role = vampire
    team = vampire

villager
    role = villager
    team = villager

baker
    role = baker
    team = villager


重要：

「役職」と「陣営」を同じものとして扱わない。

将来的に、

狂人
    role = madman
    team = wolf

のような特殊役職を追加できるようにする。


# ============================================================
# プレイヤーへの設定
# ============================================================

最終的に各プレイヤーについて、

{jinro.role::プレイヤー}
{jinro.team::プレイヤー}
{jinro.alive::プレイヤー}

を保持する。


例：

Player 1
    role = wolf
    team = wolf
    alive = true

Player 2
    role = vampire
    team = vampire
    alive = true

Player 3
    role = villager
    team = villager
    alive = true


# ============================================================
# 役職再設定時の安全処理
# ============================================================

役職を再設定するときは、古い役職情報を必ず削除してから
新しい役職を設定する。

最初に、

delete {jinro.role::*}
delete {jinro.team::*}
delete {jinro.alive::*}

を実行する。

その後、新しい役職・陣営・生存状態を設定する。

これにより、

「役職は村人なのにteamだけ以前の人狼が残っている」

などの古いデータによる誤判定を防止する。


# ============================================================
# 抽選処理
# ============================================================

役職決定時の基本処理：

1. 登録されているプレイヤー数を取得する。

2. 既存の
   role
   team
   alive
   を削除する。

3. 人狼を必須人数分確定する。

4. その他の役職についてchanceを判定する。

5. chanceに当選した役職についてcount人数を確保する。

6. すべての特殊役職人数を合計する。

7. 登録人数から特殊役職人数を引く。

8. 残った人数を村人にする。

9. 各プレイヤーにroleを設定する。

10. 各roleに対応するteamを設定する。

11. 全参加者のaliveをtrueにする。


# ============================================================
# 重要な設計思想
# ============================================================

「役職の最大人数」は持たない。

「その役職を採用する確率」と
「採用された場合の人数」を分離する。

つまり、

chance = 役職が存在する確率

count = 存在した場合の人数

とする。


村人は差分で決定する。


また、ゲームロジック側では、

「Player 1だから人狼」
「Player 2だから村人」

のような判定をしない。

必ず、

{jinro.role::%player%}
{jinro.team::%player%}

を参照して判定する。

これにより、参加人数が2人、4人、8人、16人などに
増えても同じ仕組みを利用できるようにする。
