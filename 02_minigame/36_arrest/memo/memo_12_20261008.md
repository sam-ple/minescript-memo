で固定して、**5～10人で実際にエンドラまでやってTPS/MSPTを見る**、という進め方をおすすめします。

はい。**Minecraftの身内用Paperサーバーとして8GBは、かなり普通～余裕のある設定**です。

## 1. Chunkyを入れる

Paper用のChunkyを導入します。

公式配布元から **ChunkyのPaper対応版**を入れて、

```text

```

という状態にします。

既にサーバーを起動しているなら、一度停止してから入れるのが安全です。

## 2. サーバーを起動

いつもの

```text

```

から起動。

コンソールにChunkyの読み込みが出ればOKです。

ゲーム内で、

```mcfunction
/plugins
```

などからChunkyが読み込まれていることも確認できます。

# 3. Overworldを生成

まず通常世界です。

ゲーム内で、

```mcfunction
/chunky world world
```

とします。

現在のワールド名が `world` ならこれです。

次に中心地点を決めます。

例えば、

```mcfunction
/chunky center 0 0
```

そして半径を指定。

例えば**半径5,000ブロック**なら、

```mcfunction
/chunky radius 5000
```

最後に、

```mcfunction
/chunky start
```

です。

これで、

```text
中心 0,0
半径 5000
```

の範囲を順番に事前生成します。

---

## 4. 生成中は何もしなくていい

Chunkyが生成している間は、サーバー側でかなりCPUを使います。

なのでこれは、

**人が遊んでいない時間にやる**

のがおすすめです。

例えば寝る前に開始しておいて、

```text
Chunky生成
↓
朝には完了
↓
本番
```

という使い方が楽です。

生成状況は、

```mcfunction
/chunky progress
```

で確認できます。



のような独立ワールドとして作っているなら、その名前を指定します。

今回なら私は最初、

**半径5,000はかなり広いです。**

なので、チャンク数もかなり多くなります。

「5,000だから5,000チャンク」ではありません。

そのため、**最初のテストとしては半径2,000～3,000程度から始める**のも全然アリです。

という考え方でいいです。

### まず `/mv create arrest normal` について

Multiverse-Coreで、

```mcfunction
/mv create arrest normal
```

と作った場合、これは基本的に**通常のOverworldタイプのワールドを1つ作る**コマンドです。

つまり、

```text

```

というOverworldができるだけで、

```text
arrest_nether
arrest_the_end
```

が自動的にセットで作られる、という考え方ではありません。

Nether・Endを使うなら、**別途ワールドを作る／既存ワールドを利用する**などの構成を決める必要があります。

---

## Chunkyの「0,0」は何なのか

Chunkyの

```mcfunction
/chunky center 0 0
```

は、

**「プレイヤーのスタート地点を0,0にする」**

という意味ではありません。

単純に、

> **「この座標を中心にチャンクを事前生成してください」**

という意味です。

例えば、

```text
/chunky center 0 0
/chunky radius 3000
```

なら、

```text
          3000
     ┌───────────┐
     │           │
     │     ●     │
     │   0,0     │
     │           │
     └───────────┘
          3000
```

という範囲を生成するイメージです。

---

# じゃあスタート地点はどうする？

これはChunkyとは別問題です。

例えば、

```mcfunction
/setworldspawn 0 0 0
```

などでワールドのスポーン地点を決められます。

Multiverseを使っているなら、**ロビー・ゲーム開始地点を別途設定する**こともできます。

なので、

```text
スタート地点
    ↓
ゲーム設計の問題

Chunkyの中心
    ↓
事前生成する範囲の問題
```

として分けて考えればOKです。

---

# Netherは「どこに入るか分からない」問題

これはその通りです。

ただ、**Netherは「入口の場所を全部予測して生成する」必要はありません。**

例えばOverworldの、

```text
0,0
```

付近にネザーポータルを作った場合、対応するNether側の位置は基本的に座標換算されます。

概念的には、

```text
Overworld
X 800
Z 400

↓ Nether

X 100
Z 50
```

のように、**Overworldの座標を基準にNether側の座標が決まります。**

なので、

> 「Netherのどこに入るか分からないからNether全部をChunkyする」

必要はありません。

---

## だから今回なら

例えばゲームの活動範囲を、

```text

0,0を中心に半径5000
```

とするなら、

Netherは対応する範囲を考えて、

```text
Nether
0,0を中心に半径1250程度
```

でもかなり広いです。

ただし、プレイヤーがNetherで自由に遠征するなら、もう少し広くしてもいい。

---

# Endは1つだけ？

通常のMinecraftの**1つのEndディメンションにエンドラが1体**です。

そして重要なのが、

**エンドラを倒したらEndそのものが終わるわけではない**

ということ。

エンドラ討伐後も、

```text
End中央
↓
エンドゲートウェイ
↓
外島
↓
エンドシティ
↓
エリトラ
```

と探索できます。

なので、今回の「エンドラ討伐＋サバイバル」なら、**Endもある程度事前生成しておく価値があります。**

ただしEndも無限なので、

> End全部をChunkyで生成

は現実的ではありません。

---

# 「全部一度入らないといけない？」→ いいえ

これも不要です。

Chunkyは、

**プレイヤーが実際にそこへ行かなくてもチャンクを生成できます。**

だから、

```text
Overworld
↓
Chunkyで事前生成

Nether
↓
Chunkyで事前生成

End
↓
Chunkyで事前生成
```

しておけば、

**本番で初めてそのディメンションに入ったときにも、既に地形が生成済み**

という状態にできます。

## Chunkyの容量はどれくらい？

ここはかなり重要。

ざっくりOverworldで見ると、

| Chunky半径 |            生成範囲 |      チャンク数 |       容量目安 |
| -------: | --------------: | ---------: | ---------: |
|    1,000 |   2,000 × 2,000 |    約15,600 | 約100～200MB |
|    2,000 |   4,000 × 4,000 |    約62,500 | 約0.4～1GB程度 |
|    3,000 |   6,000 × 6,000 |   約140,000 | 約1GB前後～数GB |
|    5,000 | 10,000 × 10,000 |   約390,000 |   約2～4GB程度 |
|   10,000 | 20,000 × 20,000 | 約1,560,000 |  数GB～10GB超 |

実際の容量は地形・Minecraftバージョン・生成内容などで変わるので、あくまで目安。Chunky公式も、ワールドサイズは線形ではなく、生成内容によって容量が変わると説明している。([GitHub][2])

## ゲーム終了後に消す場合

ここは非常に簡単です。

つまり、

```text
world/
world_nether/
world_the_end/
```

の中に生成済みチャンクが入っています。

### 例えばARREST GAME専用ワールドなら

```text
arrest/

arrest_the_end/
```

としておけば、

**ゲーム終了**
↓
サーバー停止
↓
この3フォルダを削除
↓
次回新しくワールドを作る

でOKです。

Skriptの**保存されている変数を全部削除**するなら、基本はこれです。

```mcfunction
/skript delete variables
```

これでSkriptが保存している変数を全削除できます。

### ARREST GAMEで使う場合

サーバーを停止する必要はありません。ゲーム中ではなく、できれば一旦 `arrest off` にしてから、

```mcfunction
/arrest off
/skript delete variables
```

その後、必要なら

```mcfunction
/sk reload scripts
```

でスクリプトを再読み込みします。

### 注意

これは**Skriptが保存している全変数**が対象です。

例えば、

```text
{arrest::*}
{arrest::jail::*}
{arrest::player::*}
{linerace::*}
{jinro::*}
```

など、Skriptで保存している他ゲームの変数も全部消えます。

なので、**ARREST GAMEだけを初期化したい**場合は、全削除ではなく

```skript
delete {arrest::*}
```

のようにARREST関連だけ消す方法もあります。

今回のように「一旦全変数をまっさらにしてARREST GAMEを最初からテストしたい」という用途なら、`/skript delete variables` でOKです。
