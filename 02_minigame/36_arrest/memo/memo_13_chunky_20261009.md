Minecraftの Multiverse-Core で管理しているワールドと、サーバー標準の `world` では削除方法が異なります。

## 1. Multiverseで作成したワールド

```
/mv delete ワールド名
```

これでワールドを削除できます。

ただし、Multiverseのバージョンによって確認操作が必要です。

## 2. デフォルトの `world`

デフォルトの `world` は、基本的にサーバーを停止してフォルダを直接削除します。

ただし、重要な注意点があります。

- `world` は通常、サーバーのメインワールドです。
- 削除しても、サーバー起動時に自動生成されます。
- `world_nether` と `world_the_end` も標準の関連ワールドです。
- サーバー稼働中にフォルダを削除するのは避けてください。

## 3. 削除方法の違い

| 操作           | ワールド登録    | フォルダ  |
| ------------ | --------- | ----- |
| `/mv unload` | 残る        | 残る    |
| `/mv remove` | 解除される     | 残る    |
| `/mv delete` | 解除される     | 削除される |
| フォルダ直接削除     | 登録が残る場合あり | 削除される |

Multiverseでは、`server.properties` の `level-name` に指定されたデフォルトワールドはアンロードできない仕様です。

Skriptの変数を\*\*すべて削除（初期化）\*\*する方法は2つあります。

### 方法① コマンドで全削除

ゲーム内またはサーバーコンソールで実行します。

```
/sk clearvariables
```

ただし、このコマンドはSkriptのバージョンによって利用できない場合があります。

### 方法② ファイルから全削除（確実）

1. Minecraftサーバーを停止する。
2. 以下のファイルを開く。

```
plugins/Skript/variables.csv
```

3. `variables.csv` をバックアップしてから削除する。
4. サーバーを再起動する。

これでCSVに保存されているSkriptの変数がすべて初期化されます。

注意： SkriptがSQLiteなど別のデータベースを使用している場合は、`variables.csv` ではなく、その保存先を初期化する必要があります。

ARREST GAMEで使用している逮捕回数、収監状態、ゲーム進行状況などの変数も削除対象です。

おすすめは方法②です。 サーバー停止中に削除すれば、変数が再保存されるトラブルを防げます。

## スポーン地点の確認方法

Java版なら、以下のコマンドで確認できます。

```
/data get entity @p SpawnX
```

ただし、これはワールド全体の初期スポーン地点を調べるコマンドではありません。

確実なのは、コンパスを使う方法です。

通常のオーバーワールドでは、コンパスがワールドのスポーン地点を指します。その場所でF3を押せば座標を確認できます。

また、Minecraft Java版1.21.5以降なら、次のコマンドでワールドスポーン地点を確認できます。

```
/execute in minecraft:overworld run spawnpoint
```

ただし、これは確認用ではなく、プレイヤーのリスポーン地点を変更するコマンドなので実行しないでください。

## ディメンションごとの中心座標

| ワールド     | Chunkyの中心   | おすすめ        |
| -------- | ----------- | ----------- |
| オーバーワールド | 初期スポーン地点    | 実際に入って確認    |
| ネザー      | 最初のネザーゲート付近 | ゲートを作ってから確認 |
| エンド      | X=0、Z=0     | 固定でOK       |

### オーバーワールド

初期スポーン地点を確認して、その座標をChunkyの中心にします。

### ネザー

ネザーにはオーバーワールドのような通常の初期スポーン地点がありません。

ネザーゲートの位置によって、最初に到着する場所が変わります。

例えば、オーバーワールドのゲートが X=800、Z=400 なら、ネザー側はおおむね次の座標になります。

- X=100
- Z=50

つまり、オーバーワールドの座標を8で割った位置が目安です。ただし、実際のゲート位置は周囲の地形や既存ゲートによってずれることがあります。

ネザー半径2,000なら、中心を0,0にしても相当広い範囲をカバーできます。

### エンド

エンドの中央島とエンダードラゴンの戦闘エリアは、X=0、Z=0を中心としています。

そのため、こちらは事前に入る必要はありません。

```
/chunky world world_the_end
/chunky shape circle
/chunky center 0 0
/chunky radius 300
/chunky start
```

## ひとつ注意

今回、オーバーワールドの半径を3,000にする予定ですよね。

オーバーワールドで要塞（エンドポータル）が半径3,000より遠くに生成される可能性もあります。

ただし、Chunkyの範囲外でも通常どおりチャンクは生成されるため、ゲーム進行上の問題はありません。

私なら次の順番にします。

1. オーバーワールドを新規生成する。
2. 一度ログインして初期スポーン座標を確認する。
3. その座標を中心に半径3,000を事前生成する。
4. ネザーは0,0を中心に半径2,000を生成する。
5. エンドは0,0を中心に半径300を生成する。

これなら、実際にネザーやエンドへ行く前に3ワールドすべての事前生成を完了できます。
