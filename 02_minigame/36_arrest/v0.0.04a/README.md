# ARREST GAME v0.0.04a — 現在の全体構成

## 1. 基本コンセプト

ARREST GAMEは、

> **Minecraftの通常サバイバル中に、特定の行動を「犯罪」として検知し、その場に牢屋を生成してプレイヤーを収監するゲーム**

です。

基本ループは、

```text
プレイヤーが行動
      ↓
犯罪判定
      ↓
犯罪成立
      ↓
arrest_crime()
      ↓
罪状・刑期・保釈金を取得
      ↓
牢屋生成
      ↓
プレイヤー収監
      ↓
BossBarで刑期表示
      ↓
 ┌───────────────┐
 │               │
 ↓               ↓
保釈金を払う     刑期を待つ
 │               │
 └───────┬───────┘
         ↓
      牢屋解放
```

# 3. `arrest.sk`

### 役割

**ARREST GAMEそのものの管理。**

ここはゲーム全体の入口です。

イメージとしては、

```text
/arrest on
/arrest off
/arrest status
```

などを管理。

### 管理するもの

* ARREST GAME ON/OFF
* 対象ワールド
* ゲーム全体の状態
* 必要な初期化

つまり、

> 「今、ARREST GAMEを動かしているのか？」

を管理するファイルです。

---

# 4. `config/`

ここは**設定置き場**です。

犯罪の処理そのものを書かず、

> 「この犯罪は何秒？ 保釈金はいくら？」

を管理します。

---

## `config/general.sk`

### 役割

ゲーム全体の設定。

例えば、

```text
対象ワールド
ゲームON/OFF
共通設定
```

など。

今後、

```text
牢屋の大きさ
共通刑期
ゲームモード
```

など、犯罪以外の全体設定が増えたらここ。

---

# 5. `config/crimes.sk`

ここはかなり重要です。

**犯罪ごとの設定を一元管理するファイル。**

例えば概念的には、

```text
crime-id: flower

name:
    花踏み罪

jail-time:
    120

bail-item:
    copper ingot

bail-amount:
    3

bail-name:
    銅インゴット
```

という感じ。

そのため犯罪ファイル側では、

```skript
arrest_crime(player, "flower")
```

だけで済みます。

---

## この構造のメリット

例えば、

> 花踏み罪を30秒 → 2分にしたい

となった場合、

**`flower.sk`を変更する必要がありません。**

`config/crimes.sk`だけ変更。

```text
crime/flower.sk
       │
       │ 「flowerです」
       ↓
core/crime.sk
       │
       ↓
config/crimes.sk
       │
       ├─ 花踏み罪
       ├─ 2分
       ├─ 銅
       └─ 3個
```

という構造です。

これは今後のバランス調整にかなり便利です。

---

# 6. `config/messages.sk`

### 役割

メッセージ関係をまとめる場所。

例えば、

```text
逮捕しました
保釈しました
鉄インゴットが足りません
刑期終了
```

など。

今は日本語ですが、将来的に、

```text

EN
```

つまり、

```text

   ↓
メッセージ
   ↓
日本語 / 英語
```

という分離をしやすくしています。

# 7. `core/`

ここが**ARREST GAMEのエンジン部分**です。

犯罪そのものではなく、

> 「犯罪が成立した後、ゲームとして何をするか」

を担当します。

---

# 8. `core/crime.sk`

### 役割

**全犯罪共通の受付窓口。**

犯罪ファイルから、

```skript
arrest_crime(player, "flower")
```

のように呼ばれます。

処理の流れは、

```text
crime/flower.sk
       ↓
arrest_crime(player, "flower")
       ↓
ARREST GAME ON?
       ↓
対象ワールド?
       ↓
収監中ではない?
       ↓
犯罪が有効?
       ↓
config/crimes.sk
       ↓
罪状・刑期・保釈金取得
       ↓
arrest_create_jail()
```

です。

つまり、

> **すべての犯罪が最終的にここを通る**

のがポイント。

また、今後Survival限定にする場合も、ここで共通判定すれば全犯罪に適用できます。

---

# 9. `core/jail.sk`

### 役割

**牢屋そのものを管理する中心ファイル。**

ここがARREST GAMEの中核です。

主な機能：

* 牢屋生成
* 牢屋情報保存
* プレイヤーと牢屋IDの紐付け
* 保釈
* 牢屋撤去
* 看板設置
* 看板による保釈
* 牢屋破壊防止

---

# 10. 牢屋のデータ管理

牢屋にはIDがあります。

概念的には、

```text
arrest::jail::1
arrest::jail::2
arrest::jail::3
...
```

という形。

各牢屋に、

```text
active
player
uuid
reason
world
x1
x2
z1
z2
floor
ceiling
time
max-time
sign::
```

などを保存しています。

これによって、

**複数人が同時に逮捕されても、それぞれ別の牢屋として管理できます。**

# 11. `core/bossbar.sk`

### 役割

**刑期の表示・時間管理。**

牢屋生成時、

```text
残り時間：2:00
```

などをBossBarで表示。

時間が経過すると、

```text
2:00
 ↓
1:59
 ↓
1:58
 ↓
...
 ↓
0:00
```

となり、0になったら、

```text
刑期終了
 ↓
牢屋解放
```

です。

また、現在は時間切れ時のサウンドもここから呼び出します。

---

# 12. `core/protection.sk`

### 役割

**収監中のプレイヤー保護。**

現在確定しているもの：

* ダメージ無効
* 満腹度変化なし
* 耐性V
* 水中呼吸
* 火炎耐性
* ポーションアイコン非表示
* ポーションパーティクル非表示

つまり、

> **牢屋に入っている間はゲーム上の外的要因で不利益を受けない**

ようにしています。

また、犯罪判定側でも収監中なら犯罪処理を止めるため、牢屋の中でさらに罪を重ねることもありません。

---

# 13. `core/sound.sk`

v0.0.04aで追加した部分です。

**音を各犯罪ファイルに分散させず、ここで集中管理。**

現在の主な音：

### 逮捕

```text
block.iron_door.close
```

### 保釈

```text
entity.player.levelup
```

### 刑期終了

```text
block.note_block.pling
```

そして重要なのが、

**対象プレイヤーにだけ再生する**

という設計。

例えばAさんが逮捕された場合、

```text
Aさん → 🔊
Bさん → 無音
Cさん → 無音
```

です。

# 14. `crime/`

ここは**犯罪の検知だけを担当する場所**。

これが非常に分かりやすいです。

例えば花なら、

```text

     ↓ YES

```

だけ。

つまり、

> 犯罪ファイルは「逮捕後どうするか」を知らない。

これが現在の設計の大きなポイントです。
